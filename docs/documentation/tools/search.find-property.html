Property search

Finds every occurrence of a key (JSON) or element or attribute name (XML) and lists its path, kind, line, column and value.

MCP name search__find-property · tool id search.find-property · Search · read-only

  • When to use it
  • Inputs
  • Options
  • Outputs
  • Diagnostics
  • Limits
  • Examples (5)

When to use it

  • You know a field name and want every place it occurs, at any depth.
  • You want to check whether a document contains a field at all, such as password or ssn.

When another tool fits better

  • Value search (search__find-value): You know the value, not the name.
  • JSONPath query (search__jsonpath): You need a condition on the values.

Inputs

text required text Document
The JSON or XML document to search. A file path can be given in textFile instead.
Example: {"customer":{"email":"ana@example.com"}}

Options

query string, default Query
The property name to find; in regex mode a JavaScript regular expression of at most 1000 characters. (at least 1 characters, at most 1000 characters)
Example: email
mode enum, default exact Match mode
exact: the whole text equals the query (default). contains: the query is a substring. regex: the unanchored regular expression finds a match.
  • exact: the whole text equals the query
  • contains: the query is part of the text
  • regex: a JavaScript regular expression finds a match (not anchored)
caseSensitive boolean, default true Case sensitive
Default on. Off folds both sides with toLowerCase; in regex mode it adds the i flag.
Off folds both sides to lower case; in regex mode it adds the i flag.
regexFlags string, default (empty) Regex flags
Regex mode only: any of i m s u, each at most once. Other flags are refused. (at most 4 characters)
Only i, m, s and u, and only in regex mode.
Example: i
format enum, default auto Document format
auto reads the document as XML when its first non-blank character is <, else as JSON.
  • auto: XML when the first non-blank character is <, else JSON
  • json: read as JSON
  • xml: read as XML
xmlTargets enum, default both XML targets
XML only: search element names or text, attribute names or values, or both (default).
  • both: elements and attributes
  • elements: elements only
  • attributes: attributes only
maxResults integer, default 1000 Maximum rows
At most this many rows are listed (default 1000, up to 100000); the total number of matches is always reported. (minimum 1, maximum 100000)
The total number of matches is always reported.
previewLength integer, default 200 Value length
A value longer than this many UTF-16 units is shortened and ends with … (default 200, 10 to 2000). Line breaks show as escapes. (minimum 10, maximum 2000)
Example: 40

Outputs

results table
One row per result: path, kind (string, number, boolean, null, object, array, element, attribute, text), line, column and value. Long values are shortened to previewLength and end with an ellipsis.

Diagnostics

Messages the tool can return, last in the result, as severity CODE: message (line, column). Codes that any tool can return are listed in the overview.

E_SEARCH_QUERY error
The query is empty.
E_SEARCH_REGEX error in an example below
The regular expression is not valid, or too long; a syntax error ends with (query column N) when its cause can be placed.
E_SEARCH_REGEX_FLAGS error
A regex flag other than i, m, s, u was given, or one was repeated.
E_JSON_SYNTAX error
The document is not valid JSON.
E_XML_SYNTAX error
The document is not well-formed XML.
I_SEARCH_NO_MATCH info
Nothing matched; the table has only its header.
W_SEARCH_TRUNCATED warning
More matches than maxResults; the message gives the total.
W_SEARCH_SKIPPED warning
A very long value was not tested against the regular expression.
I_PROBLEMS_DROPPED info
More warnings were found than are listed.
W_JSON_DUPLICATE_KEY warning
The document repeats a key; both members are searched.

Limits

  • XML names are matched as written, so a prefix is part of the name: p:price, not price, in exact mode.
  • Containers are listed with a summary such as {2 members}, not their full content.

Examples

Every email key

The typical case: all three email keys are found, each with its path and position.

You send

Tool search__find-property

text

{
  "store": "Example Shop",
  "orders": [
    {"id": "A-1", "paid": true, "total": 24.90, "customer": {"email": "ana@example.com"}},
    {"id": "A-2", "paid": false, "total": 9.50, "customer": {"email": "ben@example.com"}},
    {"id": "A-3", "paid": true, "total": 130.00, "customer": {"email": "cy@example.org"}}
  ]
}

Options

  • query email
This call as the MCP call
{
  "name": "search__find-property",
  "arguments": {
    "text": "{\n  \"store\": \"Example Shop\",\n  \"orders\": [\n    {\"id\": \"A-1\", \"paid\": true, \"total\": 24.90, \"customer\": {\"email\": \"ana@example.com\"}},\n    {\"id\": \"A-2\", \"paid\": false, \"total\": 9.50, \"customer\": {\"email\": \"ben@example.com\"}},\n    {\"id\": \"A-3\", \"paid\": true, \"total\": 130.00, \"customer\": {\"email\": \"cy@example.org\"}}\n  ]\n}",
    "query": "email"
  }
}

A bad pattern

An invalid regular expression is an error with the engine's reason and its column in the query.

You send

Tool search__find-property

text

{
  "store": "Example Shop",
  "orders": [
    {"id": "A-1", "paid": true, "total": 24.90, "customer": {"email": "ana@example.com"}},
    {"id": "A-2", "paid": false, "total": 9.50, "customer": {"email": "ben@example.com"}},
    {"id": "A-3", "paid": true, "total": 130.00, "customer": {"email": "cy@example.org"}}
  ]
}

  • query customer(
  • mode regex

What the server tells AI clients about this tool
Finds every occurrence of a property name in a JSON or XML document and lists its path, kind, line, column and value. JSON names are object keys; XML names are element and attribute names as written (a prefix is part of the name). Returns a table with one row per occurrence.
Outputs: results (table as CSV).
