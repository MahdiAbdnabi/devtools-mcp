Compare JSON

Compares 2 to 20 JSON documents with a base by value or structure, with arrays matched by key or in any order.

MCP name compare__json · tool id compare.json · Compare · read-only

  • When to use it
  • Inputs
  • Options
  • Outputs
  • Diagnostics
  • Limits
  • Examples (5)

When to use it

  • You want the differences between two API responses or configuration files, without noise from formatting or key order.
  • Array items moved, and you want them matched by an id.
  • You want to check that several environments return the same structure (mode structure).

When another tool fits better

  • Text diff (text__diff): You need a patch to apply, or the files are not JSON.
  • JSON formatter / minifier (json-xml__format-json): You only want to read one document.

Inputs

documents required multi-text Documents
Two to twenty documents; every one is compared with the base. A file path can be given in documentsFiles instead.
Example: {"status":"open"},{"status":"paid"}
names multi-text Names
Optional labels, one per document. A file path can be given in namesFiles instead.
Example: test,production

Options

mode enum, default values Mode
Compare the values, or only the keys and the value types.
  • values: compare values (default)
  • structure: compare only keys and value types
base integer, default 1 Base document
Which document is the reference; every other document is compared with it. (minimum 1, maximum 20)
Example: 2
key string, default (empty) Match by key
Match array items (and CSV rows) by these fields instead of by position: id or id, sku. Items must carry every field as a plain value. (at most 1000 characters)
Several fields: "id, sku". XML: an attribute such as @id, or a child element holding only text.
Example: sku
ignoreOrder boolean, default false Ignore order
Treat arrays without a key as sets: the same items in another order are equal.
For arrays without a key, such as tags.
ignorePaths string, default (empty) Ignore paths
Dot paths to leave out, one per line (or separated by ;): items.price, catalog.book.@id. Array positions are skipped. (at most 100000 characters)
One dot path per line or separated by ;. Array positions are left out of the path.
Example: updated items.price
numbers enum, default text Compare numbers
text: 10.50 and 10.5 differ (marked as the same value); value: numbers that are equal as decimals are equal, and in XML and CSV number-like text counts as a number.
  • text: 10.50 and 10.5 are different (reported as changed (same value))
  • value: numbers equal as decimals are equal
maxDiffs integer, default 1000 Most differences
Most differences listed per document; all are still counted. (minimum 1, maximum 100000)
The summary still counts every difference.
includeDiff boolean, default false Include diff
Also return a unified diff of the two documents as printed.
Only with exactly two documents.

Outputs

summary table
One row per compared document: how many items were added, removed and changed, and whether it is identical or different.
changes table
One row per difference: document, change (added, removed, changed, changed (same value)), path, base value and value. Values are JSON text, so strings carry their quotes.
sidebyside diff
A unified diff of the two documents as the tool printed them (normalised and indented). Only with includeDiff and two documents. Only with includeDiff.

Diagnostics

Messages the tool can return, last in the result, as severity CODE: message (line, column). Codes that any tool can return are listed in the overview.

E_CMP_DOCUMENTS error
Fewer than 2 documents were given, or documents is not a list.
E_CMP_TOO_MANY_DOCUMENTS error
More than 20 documents were given.
E_CMP_NAMES error
The number of names does not match the number of documents.
E_CMP_BASE error
The base is not the number of one of the documents.
E_CMP_KEY error
The key option names no field, or too many.
E_CMP_IGNORE_PATH error
An ignore path cannot be read.
E_CMP_OPTION error
An option value is not valid.
E_CMP_TOO_LARGE error
The documents together are larger than the limit.
I_CMP_IDENTICAL info in an example below
No differences were found under the chosen options.
I_CMP_NUMBER_SPELLING info in an example below
Some changes differ only in how a number is written (10.50 against 10.5); set numbers to value to treat them as equal.
I_CMP_KEY_SKIPPED info
Some items lack a plain value for the key, so that array was compared by position.
W_CMP_DUPLICATE_KEY warning
An array repeats a key value; items with the same key are paired in order.
W_CMP_IGNORE_UNMATCHED warning
An ignore path matched nothing in any document; check its spelling.
W_CMP_DIFF_OMITTED warning
The side-by-side text would be too large and was left out; the tables are complete.
I_CMP_DIFFS_TRUNCATED info
More differences than maxDiffs were found; the rest are counted but not listed.
I_CMP_DIAGNOSTICS_DROPPED info
More diagnostics were found than are listed.
E_JSON_SYNTAX error in an example below
A document is not valid JSON; the message names the document.
W_JSON_DUPLICATE_KEY warning
A document repeats a key.

Limits

  • Each document is compared with the base only, not with the others.
  • Without a key, arrays are compared by position, so one inserted item shifts every later one. Use key (or ignoreOrder for arrays of plain values).
  • Values in the changes table are JSON text: a string shows as "P-100" with quotes, a number without.

Examples

Two versions of an order

The typical case: items matched by sku, so the reordered lines are not a change, and the updated timestamp is ignored.

You send

Tool compare__json

documents [1]

{
  "id": 7,
  "status": "open",
  "updated": "2024-03-01T10:00:00Z",
  "items": [{"sku": "P-100", "qty": 2}, {"sku": "P-101", "qty": 1}]
}

documents [2]

{
  "id": 7,
  "status": "paid",
  "updated": "2024-03-05T08:30:00Z",
  "items": [{"sku": "P-101", "qty": 1}, {"sku": "P-100", "qty": 3}]
}

Options

  • key sku
  • ignorePaths updated

{
  "name": "compare__json",
  "arguments": {
    "documents": [
      "{\n  \"id\": 7,\n  \"status\": \"open\",\n  \"updated\": \"2024-03-01T10:00:00Z\",\n  \"items\": [{\"sku\": \"P-100\", \"qty\": 2}, {\"sku\": \"P-101\", \"qty\": 1}]\n}",
      "{\n  \"id\": 7,\n  \"status\": \"paid\",\n  \"updated\": \"2024-03-05T08:30:00Z\",\n  \"items\": [{\"sku\": \"P-101\", \"qty\": 1}, {\"sku\": \"P-100\", \"qty\": 3}]\n}"
    ],
    "key": "sku",
    "ignorePaths": "updated"
