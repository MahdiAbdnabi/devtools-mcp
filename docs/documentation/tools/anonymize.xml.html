Anonymize XML

Replaces attribute values, element text and names in an XML document according to a rule set; comments are removed by default.

MCP name anonymize__xml · tool id anonymize.xml · Anonymize · read-only

  • When to use it
  • Inputs
  • Options
  • Outputs
  • Diagnostics
  • Limits
  • Examples (4)

When to use it

  • You want to share an XML export or SOAP message without personal data.
  • Comments in the document may hold names or addresses.

When another tool fits better

  • Anonymize JSON (anonymize__json): The data is JSON.
  • Anonymize text (anonymize__text): The text is not well-formed XML.

Inputs

text required text XML
The XML document to anonymize. A file path can be given in textFile instead.
rules required text Rule set (JSON)
Rules that say what to find (literal, property, path, regex, column) and what to do with it (mask, fixed, pseudonym, hash, remove). A file path can be given in rulesFile instead.
See the rule set reference in the anonymize plugin page. Check a rule set with anonymize.rules.
Example: {"version":1,"rules":[{"property":"email","strategy":"pseudonym"}]}

Options

seed string, default (empty) Seed
Secret that keys pseudonyms and hashes. The same seed gives the same output; keep it private, it is not saved in rule sets. An empty or short seed makes guessing easy. (at most 256 characters)
Keep it private and use the same seed when outputs must match across files. It is not stored in the rule set.
Example: a-long-private-secret
indent enum, default 2 Indent
Indentation of the printed result.
  • 2: two spaces
  • 4: four spaces
  • tab: one tab
  • none: one line
removeComments boolean, default true Remove comments
Remove XML comments (they often hold the data you are hiding).
On by default, because comments often hold the data you are hiding. Content rules do not look inside comments that are kept.

Outputs

result text
The anonymized XML document.

Limits

  • Paths start below the root element: customer.name, not customers.customer.name.
  • An attribute is selected with @, as in property "@email"; property "email" selects only elements named email.

Examples

Attributes, elements and comments

The typical case: the email attribute is masked except its first letter, names become fixed text, and the comment that held an address is removed.

You send

Tool anonymize__xml

text

<customers>
  <!-- exported by ana@example.com -->
  <customer id="c1" email="ana@example.com">
    <name>Ana Example</name>
    <city>Utrecht</city>
  </customer>
  <customer id="c2" email="ben@example.com">
    <name>Ben Sample</name>
    <city>Gouda</city>
  </customer>
</customers>

rules

{
  "version": 1,
  "rules": [
    {
      "property": "@email",
      "strategy": {
        "type": "mask",
        "keepFirst": 1
      }
    },
    {
      "path": "customer.name",
      "strategy": {
        "type": "fixed",
        "value": "Person"
      }
    }
  ]
}

What the server tells AI clients about this tool
Replace attribute values, text and names in XML, driven by a rule set. Paths start below the root element. Returns the anonymized document. Rules that match nothing and literals that survive are reported; the tool does not find sensitive data by itself.
Outputs: result (text).
